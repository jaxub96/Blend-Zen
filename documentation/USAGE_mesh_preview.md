# Using Mesh Preview + Building a Gothic Asset Library

## How it works

When you click "Load Mesh Preview" on a `zCVob:` object, three things
happen in order:

1. **Name resolution.** The vob's name (minus the `zCVob:` prefix, minus
   anything after a dot) is used as a mesh filename to search for -
   exactly the same convention the exporter itself already uses for the
   `visual` property. `zCVob:NW_CITY_CANDLE_01` looks for
   `NW_CITY_CANDLE_01.MRM`.
2. **Search.** Configured directories (currently a hardcoded list in
   `zen_waypoint_tools.py`, `MESH_SEARCH_PATHS` - preferences UI for this
   is a planned next step) are searched case-insensitively for that
   filename. `.MRM` is Gothic's *compiled* mesh format - what shipped
   assets actually are - not `.3ds` (the editable source format, mostly
   relevant only for your own in-progress custom meshes).
3. **Import + parent.** The real mesh is imported via KrxImpExp's own
   `krxmrmimp` importer (the same one used to bring any Gothic mesh into
   Blender), then parented under the vob empty so it inherits the vob's
   position/rotation automatically.

The imported mesh is a **completely separate object** from the vob
empty - it lives in its own `"Zen VOB Previews"` collection, is tagged
with a `zen_is_preview` custom property, and gets a `(preview)` suffix.
This is deliberate: the vob empty is the only thing the exporter ever
reads (name + transform), so nothing about the preview system can affect
what actually gets written to the uncompiled ZEN. You can delete, hide,
or ignore preview objects freely - re-running "Load Mesh Preview"
replaces the old preview rather than duplicating it.

## How to use it, step by step

1. Add a prop with **Add Other VOBs > Vob (Mesh Prop)**, naming it
   exactly after a real mesh (see the catalog below for what's
   available) - e.g. `NW_CITY_CANDLE_01`. This creates
   `zCVob:NW_CITY_CANDLE_01`.
2. With that object active, click **Load Mesh Preview**.
3. The real mesh appears, parented to the empty. Move/rotate the empty
   as normal - the preview follows automatically.
4. If you're not sure a name is correct, check the asset catalog first
   (below) rather than guessing - a typo'd name just means "no mesh
   found," reported as a warning, not an error that blocks anything.
5. When your scene looks right, **Export Uncompiled ZEN** as usual - the
   preview objects are correctly ignored by the exporter (they don't
   have a recognized name prefix), only the `zCVob:` empties are read.

## Building a Gothic asset library

The core problem this solves: you have 1351 real compiled meshes on
disk, and typing an exact matching name from memory isn't realistic.
Two pieces now exist for this:

### 1. The generated catalog

`asset_catalog/gothic2_meshes.json` - every mesh currently in your
`_compiled` directory, grouped by prefix. Generated by scanning the
folder directly, so it's exactly what's actually on disk, not a
hand-maintained guess. Re-generate it any time your mesh library changes
(the scan-and-group script is simple enough to re-run whenever - happy
to make that a proper repeatable script rather than a one-off if you'll
want to refresh it often).

The prefix groupings are useful for browsing even without knowing exact
names. Biggest categories found: `NW_` (214 - looks like general
city/world decoration), `ITMW_` (112 - melee weapons), `OC_` (110 -
looks like interactive-object-class meshes, e.g. `oCMobInter` furniture),
`ITMI_` (98 - misc items), `ADDON_` (95 - Night of the Raven-specific
assets), `OW_` (89 - Gothic 1 world assets ported into G2), `EVT_` (76 -
one-off scripted/quest objects), `ITRU_`/`ITSC_`/`ITAR_`/`ITAT_` (runes,
scrolls, armor, and what look like ring/amulet-style items
respectively). Take these interpretations as my best read of the naming
patterns, not confirmed - you'll know the actual conventions from having
worked with the game's content directly, so treat this as a starting
point to correct rather than authoritative.

### 2. What's still manual today

Browsing `gothic2_meshes.json` by hand (or `grep`-ing it) is the current
workflow for "what should I name this vob." That's step 1 of a bigger
picture worth being explicit about, per `PLAN_vob_mesh_preview.md`:

* The natural next step is surfacing this catalog **inside the Add VOB
  dialog itself** - a searchable dropdown instead of a free-text field,
  so you can only ever create a `zCVob:` with a name that's guaranteed
  to resolve to a real mesh. This turns "guess a name, hope it loads"
  into "pick from what actually exists."
* Since you mentioned already having full item-instance-to-mesh mapping
  data, `oCItem:` support (plan step 3) becomes much more direct than
  the plan assumed - rather than the heuristic-then-lookup-table
  approach, we can likely go straight to a real
  `item_mesh_map.json` sourced from your existing data. Worth doing
  together once you're ready to share that mapping format.
* Texture library: KrxImpExp already has its own texture search-path
  system (used automatically during import for materials) - nothing
  needed there, it already found and applied materials/textures
  correctly in the candle test without any extra setup from us.

## Quick reference: what goes where

| You want to... | Do this |
|---|---|
| Add a static prop with a real mesh | Add Other VOBs > Vob, name = mesh filename (check catalog) > Load Mesh Preview |
| Add a waypoint | Add Waypoint at Cursor (auto-links from active) |
| Add the player start | Add Other VOBs > Startpoint |
| Add a light | Add Other VOBs > Light, tune via Custom Properties |
| Find a mesh name | Search `asset_catalog/gothic2_meshes.json` by prefix or substring |
| Export for Spacer | Export Uncompiled ZEN button |
